# v0.13.0

Compress PDF no longer destroys your text without asking.

## Two methods

The tool only ever did one thing: render every page to a JPEG and rebuild the
document from those images. That shrinks a scanned document nicely, but on a
text document it silently turns words into pictures - no selecting, no copying,
no searching, no screen reader - and often produces a *larger* file than it
started with.

There are now two methods, and the tool says what each costs:

- **Lossless** (new default) rewrites the document with object streams and
  drops anything the page tree no longer references. Text, links and metadata
  survive. Gains are modest on an already-tidy PDF and substantial on one
  exported by an office suite - which is when people reach for this tool. If
  the rewrite would come out larger than the input, the original is returned
  instead.
- **Rasterise** is the previous behaviour, with the trade-off stated in the
  option label. The quality setting applies only to this method.

## Tests

`e2e/pdf-compression.spec.ts` holds each method to its promise: lossless keeps
the page count and the font resources, rasterise keeps the page count and drops
them, low quality comes out smaller than high, an image-heavy document actually
shrinks, and lossless never returns something bigger than it was given.
