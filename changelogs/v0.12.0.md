# v0.12.0

Makes the privacy claim literally true, fixes PWA install, and stops large
files from being held twice in memory.

## Privacy

The page loaded its three typefaces from `fonts.googleapis.com`. Every visitor's
IP reached Google before a single file was touched - hard to square with "no
tracking, works offline". The fonts now ship with the app (latin and latin-ext
subsets), and with them gone the Content Security Policy no longer needs a
third-party exception: it is `'self'` throughout, plus `form-action 'none'` and
`frame-ancestors 'none'`.

A test suite now enforces this. It fails if any request leaves the origin during
load or during a real file run, if a webfont arrives from elsewhere, or if the
CSP regains a third-party host.

## Install

`public/` did not exist, so the manifest pointed at `icons/icon.svg` and got a
404 - the app could not be installed. It now ships 192, 512, maskable 512, an
apple-touch icon and an SVG favicon, plus `robots.txt`. A test checks every icon
the manifest names actually resolves.

The logo SVG was also missing a `viewBox`, which is why scaling it cropped to
one corner.

## Batch processing

Batch mode could never be entered. Single-file tools rendered a non-multiple
file input, dropping extra files kept only the first, and the "Add Files for
Batch" zone was gated on already having more than one file - a state with no way
in. The two-worker pool, `runToolBatch` and the "File X of N" status were all
unreachable.

Single-file tools now accept several files at once, except those with an
interactive panel: a crop box or page order drawn from the first file means
nothing for the rest.

## Memory

Each job used to load its input into main-thread memory, transfer it to the
worker, then wrap the returned buffer in a Blob - copying again. A 100 MB PDF
existed twice before the download link appeared.

The File objects now go to the worker directly, and results are written to the
Origin Private File System, where the browser streams them from disk. Browsers
without OPFS keep the old path.

The worker pool was fixed at two. It now follows `hardwareConcurrency`, minus
one core for the UI and capped at four - a cap rather than a core count, because
each worker can hold a whole PDF or decoded bitmap.
