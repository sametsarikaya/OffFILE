# v0.13.1

Accessibility pass. The site now scans clean against WCAG 2.1 AA, in both
themes, and a keyboard or screen reader can follow what it is doing.

## Fixed

- **Tool cards nested one control inside another.** Each card was a
  `div role="button"` wrapping the favourite button, so screen readers
  announced a button whose contents were unreachable. The title is now a real
  link stretched over the card, with the star as its sibling - 38 violations on
  the home page alone.
- **The drop zone did the same**, carrying `role="button"` and a tab stop while
  containing a button and a file input. It is a labelled region now; keyboard
  users reach the "Choose Files" button directly.
- **Six colour-contrast failures.** The privacy badge and the download button
  used the CTA green as text or under white text (2.06:1 and 2.24:1); the
  privacy-bar eyebrow was dimmed to 3.86:1; and in dark mode the pillar
  descriptions sat at 3.28:1. All now meet 4.5:1.

## Added

- **Skip link** to jump straight to the main content.
- **Focus moves to the new page's heading** after navigating, so keyboard and
  screen-reader users start at the top of the new content instead of the
  document root. First paint is left alone, so the skip link stays the first
  thing Tab reaches.
- **A live region announces state**: files selected, processing started,
  result ready, search result counts, and failures announced assertively.
- **The shortcuts dialog traps Tab** and returns focus to whatever opened it.
- **A visible focus ring** on every control.

## Tests

`e2e/accessibility.spec.ts` runs axe-core over the home page, a tool page, the
download state, the error state, the shortcuts dialog and dark mode, and fails
on any violation. Alongside it, keyboard tests cover the skip link, focus
placement after navigation, card links versus the star button, the dialog's
focus trap, and both live-region announcements.
