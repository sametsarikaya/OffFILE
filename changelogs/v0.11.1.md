# v0.11.1

Internal restructuring, plus two DOM defects it uncovered. No change to what
the tools do.

## Fixed

- **Searching produced duplicate element ids.** Category sections were hidden
  with `display: none` while the search rendered the same tool cards again, so
  every matching card existed twice in the page. Sections are now detached
  while a search is running and restored when it clears.
- **Oversized-file warnings appeared off screen.** The warning looked for a
  `.work-area-wrapper` element that does not exist, so it was appended to the
  end of `<body>` instead of above the work area.

## Restructured

`router.ts` was 1043 lines holding routing, both pages, the palette result view
and the footer markup, with the selected files, current options and download
cleanup living as module-level variables shared by every tool page. It is now
55 lines that map a hash to a page, with:

- `pages/home.ts` - home page and search
- `pages/toolPage.ts` - tool page and its file-selection states
- `pages/toolRun.ts` - single and batch runs
- `pages/paletteResult.ts` - palette result view
- `pages/toolSession.ts` - one visit's state, scoped to that visit
- `components/footer.ts` - privacy bar built from a pillar list
- `utils/dom.ts`, `utils/hash.ts` - shared helpers

`main.css` was 4333 lines; it is now an import list over 25 files under
`styles/`. Blocks were cut on their existing section boundaries and kept
contiguous, and the split was verified by rebuilding the sheet from its parts
and diffing declaration by declaration - 3683 declarations, identical order, so
nothing in the cascade moved.

## Tests

An E2E test now asserts no element id repeats while a search is active.
